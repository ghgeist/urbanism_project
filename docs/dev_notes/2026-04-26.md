## **Critical Problem Solved**

- **WAS interpretation needed real distribution context**: The initial WAS integration had rough amenity thresholds and no repeatable summary command. The follow-up added `scripts/summarize_was_distribution.py`, validated the loaded database, and documented the observed distribution so UI labels are backed by live data rather than guesswork.
- **Dashboard lacked a direct NWI vs WAS view**: WAS and NWI are complementary signals, but users needed a way to see where they agree or diverge. PR #31 added a Dashboard tab and scatter chart that make those relationships visible, including Hollow Neighborhood quadrant counts.
- **Upgrade Potential overstated amenity improvement**: The old Upgrade Potential logic only required an NWI improvement. PR #32 added a WAS-aware mode that requires both NWI and WAS deltas when complete WAS coverage is available, while explicitly labeling fallback results as NWI-only when WAS cannot be evaluated.
