# Lessons Learned

## 2026-02-14

- Keep test classes aligned to the function under test; misplaced tests pass but hide intent and make maintenance/debugging slower.
- For geography distance queries on a geometry-indexed table, use an indexable geometry bbox prefilter (`geometry && ST_Expand(...)`) before exact `ST_DWithin(...::geography, ...)`.
- Geocoding (Nominatim/OSM) often uses US spelling for US addresses; if the user enters UK variants (e.g. "harbour" in a street name), normalize (e.g. harbour→harbor) and retry before treating the address as not found.
- When two pages share the same URL-driven search pattern (parse params → sync state → fetch when valid, replaceState on edit, pushState on submit), extract a generic hook (e.g. `useUrlDrivenSearch`) parameterized by parse/build/canFetch/fetch so behavior and fixes live in one place. Use a ref for options to avoid effect re-running on every render when callers pass inline fetch functions.
- When adding or changing API error codes: update the backend (where the code is set), the `ErrorResponse` docstring in `api/schemas.py` (canonical list), and the frontend `API_ERROR_MESSAGES` map in `frontend/src/api/client.ts` so user-facing messages stay in sync.
- When adding an early-return in a sync effect (e.g. “skip when weJustSetParamsRef”), ask: “What state does the effect normally set? Is that state updated on the path that causes the skip?” If the effect usually calls setState(X), the code path that sets the skip flag must also set X (e.g. `updateDraft` must call `setParams(next)` when the effect skips and would have run `setParams(nextParams)`).
- For optional UI (tooltips, popovers): handle “no content” and “content cleared” explicitly—unbind/hide the element rather than only setting content to `""`—and add a test that clears the content and asserts the UI is removed or hidden.
- **Agents must not merge branches or PRs.** "Ship it" or "ready to ship" means commit, push, and leave the branch ready for the human to merge. See AGENTS.md "Agent boundaries."
- When deprecating a UI framework (e.g. Streamlit → React+FastAPI), migrate any valuable test coverage (e.g. connection-closed checks) to framework-agnostic test files before deleting framework-specific tests. Delete the framework's entry point, components, config, and deps in one pass; then grep the entire repo for stale references in comments and docstrings.
- **Grep before removing any dependency.** Before deleting a package from `requirements.txt` or `package.json`, grep the codebase for its imports (`import folium`, `from folium`, `require('...')`). A wrapper package (e.g. `streamlit-folium`) does not mean the underlying library (e.g. `folium`) is unused — the service layer may import it directly.
- When introducing a new repo-wide quality gate (like Python Ruff linting), update both user docs (`README.md`) and agent policy docs (`AGENTS.md` + platform integration standards) in the same change, and make "fix lint errors before completion" explicit so human and AI workflows stay aligned.
- When adding connection pooling or caching to a service layer, update tests that mock the old call path. If tests mock `build_summary_from_coords` but the endpoint now also calls `get_pooled_connection` before the mock fires, tests will fail with env-var errors. Mock the pool calls alongside the service mocks.
- When adding `lru_cache` to a function that tests mock at a lower level (e.g. patching the geocoder underneath `get_location`), tests must call `func.cache_clear()` in `setup_method` or the cache will return stale results from previous test runs.
- **Commit incrementally, especially before context limits.** If you create new files that other files already import, commit them immediately — don't batch them with later work. A context window reset will lose uncommitted files, leaving silent import errors that TypeScript/build will catch but `git status` won't (if gitignored).
- **Check `.gitignore` when creating directories with common names.** Python packaging patterns (e.g. `lib/`, `build/`, `dist/`) in `.gitignore` can silently ignore frontend source directories like `frontend/src/lib/`. After creating files in a new directory, run `git status` or `git check-ignore` to verify they're tracked. Use negation rules (e.g. `!frontend/src/lib/`) when needed.
- When two page-level param modules share identical logic (constants, parsing, clamping), extract the shared parts into a single module (e.g. `radiusParams.ts`) and have both import from it. The page-specific modules should only contain their unique param shape and query-string key mapping.
- With psycopg2 pooling, never return a closed/broken connection via plain `putconn(conn)`; use `putconn(conn, close=True)` to discard it, and add tests that assert closed-connection paths are discarded rather than recycled.
- When the DB is remote (e.g. Neon) or the process restarts, pooled connections can become invalid (e.g. "SSL connection has been closed unexpectedly"). Catch `psycopg2.OperationalError` in API routes that use the pool: discard the bad connection, retry once with a fresh connection; if the retry fails, return 503 (service_unavailable) so the client can retry. Add a user-facing message in the frontend `API_ERROR_MESSAGES` for the `service_unavailable` code.
- **Nominatim (OSM) is insufficient for US street-level address geocoding.** OSM has comprehensive coverage for cities, ZIP codes, and neighborhoods but lacks most US street address points. Full addresses like "123 Main St, Boston, MA 02101" return no result from Nominatim. Always pair Nominatim with the US Census Bureau Geocoder (`geocoding.geo.census.gov/geocoder/locations/onelineaddress`) as a fallback — it's free, requires no API key, and has comprehensive US street address coverage. Use `urllib.request` (stdlib) so no new dependency is required. Also: never tell users in error messages to "Try a city name or ZIP code" if the geocoder is capable of handling full addresses.

## 2026-04-17

- When component code depends on chainable/external APIs (e.g., Leaflet `L.map().setView(...).on(...)` patterns), test doubles must mirror both return contracts and event methods (`setView` returns map, `on`, `getCenter`, `invalidateSize`). Otherwise CI can pass locally in runtime behavior but fail unit tests with mock-shape errors.
- When adding a new LEFT JOIN to a service query where the joined table may not exist yet (e.g. during a phased data-ingestion rollout), make the JOIN resilient at the application layer: probe `to_regclass('table_name')` once per process, cache the result, and build the SQL conditionally. A LEFT JOIN against a missing table returns "relation does not exist" and aborts the whole query — a small startup-time probe avoids hard-coupling the API's liveness to a specific loader having run. Add tests for both the with-join and without-join query shapes.
- When adding a new GeoPandas-based ingest script, always write a read-only inspection script *first* (columns, dtypes, CRS, sample rows, and a DB-side join-rate probe when applicable). It exposes surprises (column named `ID` instead of `GEOID`, score named `WAS2019` not `WAS_2019`, ESRI:102003 CRS that needs reprojection) before they become debugging sessions during ingest. Don't write a single-row to the target table until inspection output is reviewed and thresholds/assumptions are recorded in the session doc.
- When mocking a psycopg2 cursor with plain `Mock()` in tests, default `.fetchone()` returns `Mock()` which **isn't subscriptable** — production code doing `cursor.fetchone()[0]` will fail with `TypeError: 'Mock' object is not subscriptable`. Always set `mock_cursor.fetchone.return_value = (expected_value,)` when the code under test indexes into the result. A module-level cache of such a probe (e.g. `_was_table_available`) additionally needs a test fixture with `autouse=True` that resets it between tests to prevent cross-test pollution.
